# UI 收口清单

## 文档目的

该文档用于按 `DESIGN.md` 对 `宠物生活管家 / PetLife` 的 UI 落地情况进行逐页、逐组件、逐状态验收。

这份清单不判断业务是否完成，只判断：

- 界面气质是否统一
- 页面结构是否清晰
- 组件与状态是否收口
- 文案与交互是否符合当前设计方向

## 状态定义

- `已收口`：当前页面或组件在现有功能范围内，视觉、文案、状态和交互都已统一到新版设计基线。
- `部分收口`：主界面已调整，但仍缺细节状态、反馈态、弹层态、表单态或局部旧风格残留。
- `未开始`：尚未进入新版 UI 重设计，或功能本身未开始实现。
- `依赖功能实现`：页面或状态尚不存在，需等真实功能落地后再进入 UI 收口。

## 验收基线

所有 UI 收口默认按以下标准检查：

1. 符合根目录 `DESIGN.md`
2. 避免工具化、后台化、SaaS 化、医疗系统化
3. 页面有明确视觉焦点，层级清楚，留白自然
4. 文案友好、轻松、可信，不使用“阶段说明 / 阶段性可运行 / 占位提示”式表达
5. 空状态、异常状态、加载状态、禁用状态都要被设计
6. 表单输入、校验错误、成功反馈、删除确认、弹层操作有统一语言
7. 移动端与后台端分别保持统一，不互相污染风格

## 6. 后续收口顺序建议

建议按这条顺序继续：

1. 新功能落地时，同步按本清单做页面收口，避免功能做完后再大面积返工。
2. 优先补 `认证与会话失效态 / 设置页 / 消息中心 / 宠物详情完整页` 这些高频页面。
3. 服务中心后续补更细审计态时，继续沿用当前服务页模板。
4. 后台新增真实业务页时，统一复用当前的 `hero + panel + summary` 模板，不再临时拼页面。
