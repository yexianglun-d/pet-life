# Current Delivery Status

## 文档目的

该文档用于按“完整交付标准”记录 `PetLife / 宠物生活管家` 当前真实进度。

从本次校准开始：

- 不再把“主链路打通”视为模块完成。
- 不再把“骨架页 / 占位页 / 只跑通前后端一半”的状态记为完成版。
- 除用户明确延后的 `commerce`、`device` 外，其余范围都按 `mobile-app + server + admin-web` 三端完整交付推进。

## 范围基线

当前完整交付范围：

- 用户端 App
- 服务端
- 后台管理端

当前明确允许延后：

- 商城真实交易后端
- 设备厂商接入与设备事件链路

## 当前总判断

当前项目已经完成了大量真实代码和多条业务主链路，但如果按“完整交付标准”判断：

- 健康档案、萌宠日常已经满足当前范围内的完整交付标准。
- 多数业务域仍处于 `部分完成`。
- 当前项目状态应定义为：
  - 已进入正式业务开发阶段
  - 已完成较大规模真实实现
  - 距离完整完成版仍有明显缺口

## 仍然存在的主要缺口

### 1. 用户端 App

- 登录增强已补齐验证码发送、倒计时、自动续期和登录失效恢复，但真实短信仍未接入。
- 移动端已完成无网络、请求超时、会话过期、服务端异常和返回结构异常分类；refresh token 临时网络异常不会误清本地会话。
- 个人中心已补齐设置页、城市切换、通知与权限设置、消息中心。
- 宠物主档已补齐完整详情、扩字段、删除/归档、无宠物空状态和后台宠物只读查询页，宠物问题修复等写治理仍未完成。
- 首页已补齐快捷记录、提醒中心、周报、月报，但首页专用聚合接口仍未完成。
- 健康档案已补齐疫苗、驱虫、体检、用药、体重、异常观察专用表单、下一次提醒入口和附件选择/上传/预览。
- 提醒计划已补齐用户端模板读取、模板选择、表单预填、创建、完成、跳过和周期提醒状态机。
- 萌宠日常已接入服务端媒体资源引用与预览元数据回显，并补齐用户端图片/视频选择、上传、预览和删除。
- 社区已补齐推荐、关注、同城、问答四个内容流，仍缺独立发布页、独立发帖接口、话题页、问答详情页和关注关系能力。
- 服务中心已补齐用户端首页、服务商列表/详情、评价展示、预约提交、预约记录、取消预约、已完成预约评价入口、后台城市开通配置、服务商资料/项目/时段维护、预约状态处理、评价治理和操作审计；地图定位与导航能力仍未接入。
- 通知消息已补齐站内消息中心、系统/提醒/预约列表和已读状态，但推送通道和后台模板仍未完成。
- 移动端风险确认弹层、高频表单校验错误态、保存/删除/预约/评价/设置成功反馈和陪伴式加载骨架已统一；Snackbar / Toast 全量深层组件化仍需继续收口。

### 2. 服务端

- 认证链路已补齐 refresh 与退出登录，真实验证码校验仍未完成。
- 用户资料编辑、城市切换、通知设置、后台用户列表/详情查询、通知列表、已读状态、提醒完成通知和审核结果通知已完成。
- 家庭共养主链路和后台家庭列表/详情查询接口已完成，家庭写治理仍未完成。
- 宠物删除/归档、更多字段扩展、无宠物空状态和后台宠物列表/详情查询接口已完成，问题数据修复工具仍未完成。
- 健康记录扩展字段、附件 asset_id 写入回显、媒体上传校验、附件预览元数据、家庭成员记录反查读取权限、自动提醒派生和后台健康记录查询接口已完成；对象存储/CDN 已完成配置与元数据预留，真实云厂商上传适配器仍未完成。
- 萌宠日常媒体引用、预览元数据、社区同步和后台日常内容查询接口已完成；成长时间轴已补齐健康、日常、服务预约派生和后台事件排查接口。
- 系统提醒后台列表/详情查询已完成，支持状态、类型、模式、宠物、家庭、主人、处理人、来源健康记录和提醒时间筛选；提醒模板模型、后台列表/详情/创建/更新/启停接口，以及用户端宠物可用模板读取接口已完成。
- 服务中心目录、城市开通配置、时段、预约创建/取消、预约记录、预约评价、评价状态治理、操作审计、预约通知、时间轴派生和后台运营接口已完成；推送通道、地图定位等仍未完成。

### 3. 后台管理端

- 认证仍是本地占位登录，不是真实账号体系。
- 审核中心已接入举报处理；服务端已补齐处理备注持久化、回显和审核审计日志接口。
- 用户、家庭、宠物、健康、萌宠日常、时间轴、系统提醒查询和提醒模板管理后台页面已按 OpenAPI 接入；通知模板等真实运营后台能力未完成。
- 服务商后台已进入真实维护页并补齐城市配置、评价治理与操作审计；现有服务中心后台接口已同步到 `docs/api/petlife-openapi.yaml`。

## 进度记账原则

后续进度统一按以下规则描述：

- `已完整完成`：功能在当前范围内满足完整交付标准。
- `部分完成`：已有真实实现，但仍缺关键页面、关键接口、治理能力、异常态或必要联动。
- `未开始`：仅有设计、占位、骨架或尚未进入实现。
- `当前预留`：仅用于 `commerce` 与 `device`，或用户后续明确指定延后的范围。

详细功能级进度以 `docs/project/02-feature-completion-checklist.md` 为准。
