# PRD 骨架与页面级需求（全量版）

## 1. PRD 骨架

### 1.1 文档基础信息

- 产品名称
- 文档版本
- 创建时间
- 负责人
- 适用端
- 关联原型/设计稿

### 1.2 产品目标

围绕 `宠物数字档案` 建立养宠生活平台，覆盖健康管理、萌宠日常、社区分享、本地服务、设备联动五大核心能力。

### 1.3 目标用户

- 新手养宠用户
- 城市猫狗主人
- 家庭共养用户
- 内容分享型用户
- 服务消费型用户

### 1.4 范围与非范围

#### 范围

- 宠物档案
- 健康记录与提醒
- 萌宠日常
- 社区分享
- 服务信息展示与预约入口
- 商品购买入口
- 设备接入骨架

#### 非范围

- 医疗诊断替代
- 复杂会员和商业化设计
- 重度设备控制中台

### 1.5 角色与权限

- 游客
- 普通用户
- 家庭成员
- 家庭管理员
- 宠物拥有者

### 1.6 数据对象

- 用户
- 家庭
- 宠物
- 健康记录
- 提醒任务
- 萌宠日常
- 社区帖子
- 评论互动
- 服务预约
- 商品订单
- 设备
- 设备事件

### 1.7 指标

- 建档完成率
- 首周记录率
- 7/30 日留存
- 萌宠日常发布率
- 社区互动率
- 服务预约发起率
- 设备绑定率

## 2. 核心模块需求

### 2.1 宠物档案中心

#### 目标

建立每只宠物的唯一数字身份，作为全产品数据归属主轴。

#### 关键字段

- 宠物昵称
- 品种
- 性别
- 生日
- 到家日期
- 绝育状态
- 体重
- 过敏史
- 病史
- 头像
- 备注

#### 关键规则

- 一个账号支持多宠。
- 当前宠物需要全局可见和可切换。
- 删除宠物需保留审慎的二次确认机制。

### 2.2 健康档案与提醒

#### 目标

支持结构化健康记录沉淀，并通过提醒驱动用户回访。

#### 记录类型

- 疫苗
- 驱虫
- 体检
- 用药
- 异常观察

#### 关键规则

- 每条记录必须带时间、类型、宠物、操作人。
- 记录完成后可自动创建下一次提醒。
- 异常观察只输出记录和提醒，不输出诊断结论。

### 2.3 萌宠日常

#### 目标

以低门槛方式承接用户日常记录、情感沉淀与社区内容供给。

#### 关键字段

- 图片/视频
- 标题
- 描述
- 日常标签
- 状态标签
- 可见范围
- 是否加入成长时间轴
- 是否同步社区

#### 关键规则

- 默认挂到当前宠物。
- 公开内容可一键同步社区。
- 私密内容不得进入公开流量分发。

### 2.4 成长时间轴

#### 目标

统一承接宠物生命周期内的所有关键事件。

#### 事件来源

- 健康记录
- 萌宠日常
- 服务记录
- 设备事件
- 纪念日

### 2.5 社区

#### 目标

承接晒宠、问答、经验分享和互动关系。

#### 内容类型

- 图文帖
- 视频帖
- 经验帖
- 问答帖

#### 关键规则

- 发帖可挂宠物卡片、日常记录、服务体验、商品体验。
- 必须具备举报、拉黑、审核状态。

### 2.6 服务中心

#### 目标

提供医院、寄养、洗护、训练和商城的统一承接。

#### 关键规则

- 服务和商品尽量与具体宠物绑定。
- 未开通区域只能显示预留态页面，不显示空白。

### 2.7 家庭共养

#### 目标

支持多人共同照顾同一只宠物。

#### 权限

- 拥有者
- 管理员
- 普通成员

### 2.8 设备中心

#### 目标

承接智能硬件状态与事件，并将关键数据写回宠物档案。

#### 关键规则

- 设备必须归属具体宠物。
- 设备异常进入消息中心与成长时间轴。

## 3. 页面级 PRD 明细

## 3.1 首页驾驶舱

### 页面目标

让用户在最短路径内完成一次高频动作，并感知当前宠物的整体状态。

### 核心入口

- 当前宠物卡
- 今日待办
- 快捷记录
- 萌宠日常入口
- 社区推荐
- 服务入口
- 设备状态

### 页面模块

1. 顶部区：城市、搜索、消息
2. 当前宠物卡：宠物头像、名称、年龄、今日状态、切换入口
3. 今日待办：疫苗、驱虫、体检、自定义提醒
4. 快捷记录：喂食、饮水、排便、体重、用药、记日常
5. 萌宠日常：最近一条日常或“今天记录一下 TA”
6. 社区推荐：推荐内容卡片
7. 服务入口：医院、寄养、洗护、训练、商城
8. 设备状态摘要：设备在线状态和最近异常

### 交互规则

- 若无宠物，优先展示创建宠物引导。
- 若有宠物但无记录，优先展示快捷记录和记日常。
- 待办卡片点击后进入提醒中心或对应详情。

### 埋点建议

- 首页曝光
- 快捷记录点击
- 记日常点击
- 社区推荐点击
- 服务入口点击

### 验收标准

- 用户可在 10 秒内完成一次记录。
- 用户可在首页完成宠物切换。
- 首页信息均围绕当前宠物展示。

## 3.2 宠物主页

### 页面目标

作为宠物的一站式总览页，承接健康、日常、时间轴、设备和服务入口。

### 页面模块

1. 宠物头图与基础信息
2. 健康档案入口
3. 提醒计划入口
4. 萌宠日常预览
5. 成长时间轴入口
6. 设备状态区
7. 服务推荐区

### 交互规则

- 多宠切换需无损完成。
- 所有子模块进入后默认关联当前宠物。
- 宠物主页需展示最近一次关键事件摘要。

### 埋点建议

- 宠物主页曝光
- 健康档案点击
- 萌宠日常点击
- 时间轴点击
- 设备中心点击

### 验收标准

- 宠物主页需完整展示该宠物的核心概览。
- 进入任意子模块无需再次选择宠物。

## 3.3 萌宠日常新建页

### 页面目标

以极低门槛完成一条日常记录，并可选择性进入社区。

### 表单字段

- 图片/视频
- 标题
- 描述
- 标签
- 状态标签
- 可见范围
- 是否加入成长时间轴
- 是否同步社区

### 交互规则

- 最低可只上传一张图加一句话。
- 同步社区默认关闭。
- 若用户未选择宠物，则默认挂当前宠物。

### 埋点建议

- 打开日常新建页
- 上传媒体
- 发布成功
- 勾选同步社区

### 验收标准

- 用户可在 3 步内完成日常记录。
- 发布后内容可在宠物主页和时间轴查看。

## 3.4 社区首页

### 页面目标

承接内容浏览、互动和发布入口，并强化宠物身份感。

### 页面模块

1. 顶部搜索与发布
2. Tab：推荐、关注、同城、问答
3. 内容流卡片
4. 热门话题
5. 同城内容区

### 内容卡片字段

- 作者信息
- 宠物卡片
- 图片/视频
- 标题/摘要
- 点赞、评论、收藏

### 交互规则

- 发布入口常驻可见。
- 问答内容与普通图文流可通过 Tab 明确区分。
- 同城内容依赖城市设置。

### 埋点建议

- 社区首页曝光
- Tab 切换
- 帖子点击
- 发布点击
- 互动点击

### 验收标准

- 社区首页支持四类内容流切换。
- 用户能在帖子中感知到宠物主体信息。

## 3.5 服务首页

### 页面目标

统一承接医院、寄养、洗护、训练、商城，并与当前宠物产生推荐关联。

### 页面模块

1. 顶部城市、搜索
2. 服务宫格入口
3. 当前宠物推荐服务
4. 附近医院
5. 热门商家
6. 宠物适配商品
7. 我的预约/订单入口

### 交互规则

- 推荐内容默认基于当前宠物画像。
- 暂未开通服务必须进入预留态页面。

### 埋点建议

- 服务首页曝光
- 医院点击
- 商城点击
- 推荐服务点击
- 订单入口点击

### 验收标准

- 服务首页可完整承接所有服务类入口。
- 商品与服务推荐能和宠物发生关联。

## 3.6 医院列表页

### 页面目标

帮助用户基于城市、距离、评分和服务能力快速找到适合当前宠物的医院。

### 页面模块

1. 顶部搜索框
2. 筛选区：距离、评分、营业状态、支持项目
3. 列表区：医院卡片
4. 地图入口
5. 未开通城市预留态

### 医院卡片字段

- 医院名称
- 距离
- 评分与评价数
- 营业状态
- 地址摘要
- 特色能力标签
- 最近可预约时间

### 交互规则

- 若当前宠物已选择，则优先展示适配宠物类型的医院。
- 支持切换列表视图与地图视图。
- 未开通城市需提示开通通知，而不是展示空列表。

### 埋点建议

- 医院列表曝光
- 筛选项点击
- 医院卡片点击
- 地图入口点击
- 开通通知点击

### 验收标准

- 支持按至少 4 个维度筛选医院。
- 支持进入医院详情和预约页。

## 3.7 医院详情页

### 页面目标

向用户完整展示医院基础信息、能力、评价和预约入口，提升信任感。

### 页面模块

1. 医院头图
2. 基础信息：名称、评分、营业状态、地址、电话
3. 医院能力：科室、擅长方向、设备条件
4. 医生/服务团队简介
5. 用户评价
6. 就诊须知
7. 预约按钮

### 交互规则

- 地址支持一键导航。
- 电话支持直接拨打。
- 若医院暂未开放线上预约，按钮应降级为“开通通知”。

### 埋点建议

- 医院详情曝光
- 电话点击
- 导航点击
- 预约点击
- 评价展开点击

### 验收标准

- 医院详情需完整承载信任决策信息。
- 至少支持电话、导航、预约或预约预留态闭环。

## 3.8 医院预约页

### 页面目标

帮助用户以最少步骤提交预约请求，并让医院明确知道是哪只宠物、什么问题、什么时候到。

### 表单字段

- 选择宠物
- 就诊日期
- 时间段
- 就诊需求
- 症状或备注
- 联系人
- 联系电话

### 交互规则

- 默认带入当前宠物。
- 若从异常观察页进入，自动回填症状摘要。
- 暂未接履约时仍需保留表单结构，并在提交后进入预约登记预留态。

### 埋点建议

- 预约页曝光
- 宠物选择
- 日期选择
- 提交预约
- 提交失败

### 验收标准

- 用户可完成预约信息提交。
- 预约成功后进入预约记录页或成功状态页。

## 3.9 商城首页

### 页面目标

向用户展示与当前宠物高度相关的商品推荐和分类入口，提升浏览深度与后续转化准备度。

### 页面模块

1. 顶部搜索
2. 商品分类导航
3. 当前宠物推荐
4. 热门商品
5. 品牌专区
6. 购物车入口

### 交互规则

- 推荐算法优先基于当前宠物的种类、年龄阶段和历史浏览。
- 未登录用户可浏览，但加购和下单需登录。
- 商品卡片需展示适用宠物标签。

### 埋点建议

- 商城首页曝光
- 分类点击
- 搜索点击
- 商品卡片点击
- 购物车入口点击

### 验收标准

- 商品能按分类和适配宠物维度浏览。
- 商城首页支持进入商品详情和购物车。

## 3.10 商品详情页

### 页面目标

帮助用户完成商品决策，并明确该商品是否适配当前宠物。

### 页面模块

1. 商品轮播图
2. 商品名称与价格
3. 适用宠物标签
4. 规格选择
5. 图文详情
6. 用户评价
7. 推荐商品
8. 加购与立即购买按钮

### 交互规则

- 若商品不适配当前宠物，应明确提示不推荐原因。
- 规格未选完前不可直接提交购买。
- 支持收藏与分享。

### 埋点建议

- 商品详情曝光
- 规格选择
- 加购点击
- 立即购买点击
- 评价展开点击

### 验收标准

- 用户可明确商品适配性、价格、规格和评价信息。
- 可完成加购和购买动作。

## 3.11 购物车页

### 页面目标

集中管理用户已选择商品，并支持按宠物视角回看已选商品。

### 页面模块

1. 商品分组列表
2. 勾选状态
3. 数量增减
4. 失效商品提示
5. 合计金额
6. 去结算按钮

### 交互规则

- 支持单商品勾选、全选、批量删除。
- 失效商品需与可购买商品分区展示。
- 允许展示“关联宠物”标记，便于后续复购推荐。

### 埋点建议

- 购物车曝光
- 数量调整
- 商品删除
- 去结算点击

### 验收标准

- 购物车支持数量修改和有效商品筛选。
- 结算金额实时更新。

## 3.12 结算页

### 页面目标

让用户确认收货信息、商品信息和支付金额，完成订单提交。

### 页面模块

1. 收货地址
2. 商品清单
3. 关联宠物摘要
4. 配送方式
5. 订单备注
6. 金额明细
7. 提交订单

### 交互规则

- 订单提交前需校验库存和地址。
- 若购物车内商品对应多个宠物，可按商品项保留宠物信息。
- 支持订单备注但不可影响核心结算流程。

### 埋点建议

- 结算页曝光
- 地址修改
- 提交订单
- 提交失败

### 验收标准

- 用户可完整确认订单并提交。
- 失败状态有明确原因和回退方案。

## 3.13 设备中心页

### 页面目标

汇总当前宠物关联设备的状态、关键事件和异常提醒，形成设备能力总入口。

### 页面模块

1. 已绑定设备列表
2. 设备状态摘要
3. 最近事件流
4. 异常告警区
5. 绑定新设备入口

### 交互规则

- 设备默认按当前宠物过滤。
- 离线和异常设备需置顶。
- 最近事件支持跳转到成长时间轴或设备详情。

### 埋点建议

- 设备中心曝光
- 设备卡片点击
- 绑定设备点击
- 异常事件点击

### 验收标准

- 用户可清晰看到在线、离线、异常设备。
- 支持进入绑定流程和设备详情页。

## 3.14 设备绑定页

### 页面目标

引导用户完成设备入网、账号绑定和宠物关联，建立设备与宠物的长期关系。

### 页面模块

1. 设备类型选择
2. 设备发现/扫码入口
3. 网络配置
4. 绑定宠物
5. 自定义设备名称
6. 绑定结果

### 交互规则

- 绑定流程需支持扫码和手动输入设备号两种模式。
- 绑定成功后必须选择关联宠物。
- 绑定失败需明确失败原因，如网络异常、设备已被绑定。

### 埋点建议

- 绑定页曝光
- 扫码点击
- 手动输入点击
- 绑定成功
- 绑定失败

### 验收标准

- 用户可完成设备绑定与宠物关联。
- 失败时能明确知道下一步处理方式。

## 3.15 设备详情页

### 页面目标

展示设备的运行状态、历史事件和与宠物相关的数据趋势。

### 页面模块

1. 设备基础信息
2. 在线状态
3. 最近事件日志
4. 关键数据趋势
5. 宠物关联信息
6. 解绑入口

### 交互规则

- 事件日志按时间倒序展示。
- 告警事件需可跳转到消息中心或时间轴关联内容。
- 解绑需二次确认，避免误操作。

### 埋点建议

- 设备详情曝光
- 日志查看
- 趋势查看
- 解绑点击

### 验收标准

- 设备详情可承接状态查看、日志回看和解绑动作。
- 用户能感知设备与宠物的关联关系。

## 3.16 家庭共养管理页

### 页面目标

帮助用户清晰管理家庭成员、共享宠物和权限，支撑多人共同养宠。

### 页面模块

1. 家庭基础信息
2. 成员列表
3. 邀请成员入口
4. 共享宠物列表
5. 角色权限说明
6. 最近协同记录

### 交互规则

- 只有拥有者和管理员可修改成员权限。
- 普通成员默认不可删除宠物或修改关键健康档案。
- 邀请流程需支持链接、手机号或二维码形式扩展。

### 埋点建议

- 家庭共养页曝光
- 邀请成员点击
- 权限修改点击
- 成员移除点击

### 验收标准

- 用户可查看成员与角色。
- 管理员可完成邀请、移除、角色调整。

## 3.17 邀请家庭成员页/弹层

### 页面目标

让现有用户能快速拉新家庭成员加入同一养宠协作空间。

### 页面模块

1. 被邀请人手机号或分享方式选择
2. 邀请身份选择
3. 共享宠物选择
4. 邀请结果提示

### 交互规则

- 邀请时必须明确共享哪些宠物。
- 邀请默认角色为普通成员。
- 被邀请方加入后自动建立 `family_members` 关系。

### 埋点建议

- 邀请方式点击
- 邀请发送成功
- 邀请发送失败

### 验收标准

- 支持发起邀请并看到邀请状态。
- 邀请结果可在家庭页回看。

## 3.18 订单与预约记录页

### 页面目标

统一沉淀商品订单和服务预约，让用户有明确的交易与履约回看入口。

### 页面模块

1. Tab：商品订单、服务预约、医院预约
2. 状态筛选
3. 列表卡片
4. 详情跳转

### 交互规则

- 不同类型记录分 Tab 查看，避免状态机混乱。
- 列表卡片需展示关联宠物，强化数据闭环。

### 埋点建议

- 记录页曝光
- Tab 切换
- 订单点击
- 预约点击

### 验收标准

- 用户可统一查看商品订单和服务预约。
- 每条记录可追溯到对应详情或源页面。
